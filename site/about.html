Who built this

I build intelligent systems.

I'm Charan — an AI & Automation Engineer in Bangalore. I ship production LLM systems: a Springer-published model that reads chest X-rays well enough for a radiologist to take seriously, and document pipelines that run themselves once you stop watching them.

Before any of that, I wrote real-time control code for jet engines at DRDO. That job teaches you something the notebook never will: a millisecond of lag isn't a bug — it's a flameout. I've been suspicious of code that only works when someone's watching ever since.

What I learned building this

Five things CRUCIBLE taught me.

01 · Judgment

An automated gate is a target, not a truth

Tell a model to make the tests pass and it can write assert True and call it a day. Every objective check I added, I then had to ask: what's the laziest way to satisfy this without doing the work? That question shaped the rubric more than any design doc did.

02 · Sampling

Best-of-N is weak if the N are the same

My first tournament ran three identical prompts and picked a winner from three nearly identical answers. Real gains only showed up once each candidate got a different emphasis — simplicity, robustness, structure. Diversity is the product; sampling is just the mechanism.

03 · Testing

You can't test unpredictability — so fake it

The interesting logic here decides which of three model outputs wins. That's untestable against a real model. So the suite ships a fake CLI that speaks the same JSON envelope and hands each candidate deliberately different quality. "Did the right one win?" became an assertion instead of a hope.

04 · Memory

Fresh context beats accumulated context

Every round starts a brand new session. It feels wasteful right up until you watch a long-running session start defending its earlier decisions. The repo on disk is the state. Nothing else needs to remember anything.

05 · Human

Knowing when to stop is the whole job

I built this because I was the loop — pasting errors back in, eyeballing diffs, quietly moving the goalposts when I got tired. Writing the stop rules down as code was uncomfortable, because it meant admitting how arbitrary mine had been.

06 · The door

There's more where this came from

This is one project. The rest of them — the X-rays, the pipelines, and a few jet engines — live at charanreddy.dev. Fair warning: the jet engine stories are better than this one.
